## Background

Two GitHub repos, both owned by the user (fordp2002):

- **PyAcornDFS** (https://github.com/fordp2002/PyAcornDFS) is a Python 3 hobby project for manipulating Acorn DFS `.ssd` and `.mmb` disc images. `PyAcornDFS.py` is the library and `DFS_GUI.py` is the Tkinter GUI. The GUI opens an image into a tree view, and you right-click → Save to export files.
- **py8dis** (https://github.com/fordp2002/py8dis) is a fork of ZornsLemma/py8dis, a programmable static tracing disassembler for 6502/65C02/8080. It outputs BeebASM by default. It is driven by a Python control script that calls `load()`, `entry()`, `label()` and so on, then `go()`.

The user wanted a disassembler option in the DFS manager, so they copied the DFS manager code into the py8dis fork. Right now the fork contains `py8dis/DFS_GUI.py`, a README section on running it in a virtual environment, and a drag-and-drop package in `requirements.txt`. The user has decided **this was a bad idea**. The goal is two separate repos, with py8dis pulled into PyAcornDFS as a library and no functionality lost.

## Target design

- **PyAcornDFS is the application.** It owns everything Acorn-specific: image handling, the GUI and the "Disassemble" action.
- **The py8dis fork goes back to matching upstream ZornsLemma/py8dis**, with no DFS code in it, so upstream fixes keep merging cleanly. Any change it really needs (packaging, say) should be small and general enough to offer upstream as a PR.
- **Exactly one module in PyAcornDFS (`disasm.py`) knows py8dis exists.** The GUI only calls that module.

### `disasm.py` contract

```python
def disassemble(data: bytes, load_addr: int, exec_addr: int, name: str,
                out_dir: Path | None = None) -> DisasmResult
```

- `DisasmResult` holds the BeebASM text, the generated control script and any stderr.
- Implementation (option A, do this first):
  1. Write `data` to a temp file.
  2. Generate a py8dis control script from the DFS catalogue: `load(load_addr, path, "6502")`, `entry(exec_addr)`, `go()`. Use the real py8dis API names and signatures. **Check them against the code in `external/py8dis`; don't take them from this brief.**
  3. Run it with `subprocess.run([sys.executable, script], env={..., "PYTHONPATH": <submodule's py8dis package dir>}, capture_output=True, text=True, timeout=...)`.
  4. Return stdout as the listing. Optionally save `NAME.6502` and the control script `NAME.py` side by side. The control script is worth keeping because the usual py8dis workflow is to refine it by hand.
- Why a subprocess: py8dis appears to keep its state in module-level globals, and `go()` reads the command line and writes to stdout. **Verify this in the source.** Running it out of process avoids state leaking between runs inside a long-lived GUI, keeps a py8dis crash from taking the GUI down, and needs no changes to py8dis.
- DFS addresses: the 18-bit load/exec values may have the high bits set (`&FFxxxx` = I/O processor). Mask them down to 16 bits for the 6502 address and carry the high bits through to a comment.
- `is_available() -> bool`: the GUI hides or greys out "Disassemble" when py8dis can't be found, so the DFS manager still works without the submodule.
